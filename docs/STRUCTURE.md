# Структура myHabbit

```text
myHabbit/
├── public/                  # PWA і все, що доступне браузеру
│   ├── index.html           # єдина головна HTML-сторінка
│   ├── app.js               # активна логіка клієнта
│   ├── styles.css           # активні стилі
│   ├── sw.js                # активний Service Worker
│   ├── manifest.webmanifest
│   ├── assets/
│   │   ├── achievement-icons/
│   │   └── stickers/        # постійний шлях стікерпаків
│   ├── content/             # JSON-контент без серверного коду
│   └── icons/               # PWA та UI-іконки
├── src/
│   ├── worker.js            # активна точка входу Cloudflare Worker
│   ├── config/              # місце для майбутніх конфіг-модулів
│   ├── modules/             # місце для поступового винесення доменів
│   ├── services/            # місце для інтеграцій і сервісів
│   └── utils/               # місце для спільних утиліт
├── scripts/                 # перевірки та службові скрипти
├── docs/                    # документація
├── wrangler.jsonc
├── package.json
├── VERSION
└── CHANGELOG.md
```

## Незмінні правила

1. Не переміщувати `public/assets/`.
2. Не переміщувати `public/assets/stickers/` і не змінювати URL стікерів без окремої міграції.
3. Не створювати статичні файли PWA у корені репозиторію.
4. Не перейменовувати активні файли із суфіксами `final`, `fixed`, `new`, `copy`.
5. Тимчасові recovery/legacy файли не використовувати як основу нових функцій.
6. Нові JSON-набори додавати до відповідної категорії в `public/content/`.
7. Кожен патч повинен проходити `npm run check` і `npm run validate`.

## Поступова модульність

`src/worker.js` поки залишається робочим монолітом, щоб не ризикувати стабільністю. Нові великі функції надалі можна виносити до `src/modules/`, а спільну логіку — до `src/services/` і `src/utils/`. Винесення виконується окремими перевіреними патчами, а не масовим переписуванням.
